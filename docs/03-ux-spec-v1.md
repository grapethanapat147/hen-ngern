# 03 — UX Spec v1 (ล็อกสำหรับ prototype เมื่อผ่าน Gate 1)

วันที่: 26 ก.ย. 2026 · ฐาน: `reference/chatgpt-ux-handoff-draft.md` (flow, wireframe, microcopy, game feel) · ปรับโดย Claude ตามการตัดสินรอบ 2 ใน `00-decision-review.md`

ใช้ของ ChatGPT เป็นฐานทั้งหมด **ยกเว้น** จุดที่เอกสารนี้ระบุว่าเปลี่ยนหรือเพิ่ม

## 1. สิ่งที่ล็อก

- ครูมัธยมรัฐเป็นกลุ่มแรก · เกมสดแบบ Kahoot · นักเรียนใช้ชื่อเล่นหรือชื่อกลุ่มเท่านั้น
- ตัวเลือกผิดทุกตัวผูกกับ **มโนทัศน์** (concept) ≤ 5 เรื่องต่อชุด
- **คลังข้อทบทวน** 1 ข้อต่อมโนทัศน์ และต้องมีอย่างน้อย 3 ข้อ · ต้องเป็นข้อใหม่ ไม่ใช่ข้อเดิมในเกม
- ครูอนุมัติทุกข้อ (ข้อหลัก + คลังข้อทบทวน) ก่อนเปิดเกม · แก้หลังอนุมัติ = กลับเป็น "รอตรวจ"
- ระหว่างคาบ **ไม่มี AI สร้างข้อใหม่** ระบบเลือกจากคลังที่อนุมัติแล้วเท่านั้น
- รอบทบทวน **ไม่คิดอันดับ** · จอใหญ่แสดงผลรวมเท่านั้น ไม่เปิดเผยว่าใครตอบผิด
- "ส่งคำตอบแล้ว" แสดงเมื่อ server ตอบรับแล้วเท่านั้น (กฎของ ChatGPT §5)

## 2. คำที่ใช้ใน UI (ใช้คำเดียวกันทุกจอ)

| ความหมาย | คำใน UI | ห้ามใช้ |
|---|---|---|
| หน้าวิเคราะห์หลังเกม | จุดที่ควรทบทวน | แผนที่ความเข้าใจผิด (ใช้ในเอกสารภายในได้) |
| รอบหลังเกม | รอบทบทวน | รอบซ่อม, ข้อซ่อม |
| ข้อในคลัง | ข้อทบทวน / คลังข้อทบทวน | คลังข้อซ่อม |
| ป้ายบนตัวเลือกผิด (จอครูเท่านั้น) | ความเข้าใจผิด: … | – |
| ผู้เล่นแบบกลุ่ม | ชื่อกลุ่ม | ทีม (เลี่ยงให้สั้นและตรง) |

เหตุผล: "ซ่อม" ในโรงเรียนไทยชวนนึกถึง "สอบซ่อม" ของเด็กที่ตก

## 3. Flow ที่เพิ่มหรือเปลี่ยนจาก ChatGPT

### 3.1 ครูสร้างเกม (ChatGPT ยังไม่มีขั้น AI)

```
สร้างเกม → เลือก [วางข้อความ] หรือ [อัปโหลด PDF] + ระดับชั้น + จำนวนข้อ (5–10)
→ กำลังร่างคำถามจากเอกสาร…
→ หน้ามโนทัศน์: รายการ ≤ 5 เรื่อง (แก้ชื่อ/รวมเรื่องได้)
→ ตรวจข้อหลักทีละข้อ (wireframe ของ ChatGPT + แผง "ที่มาในเอกสาร")
→ ตรวจคลังข้อทบทวน
→ ตรวจความพร้อม → เลือกโหมด (รายคน/กลุ่ม) + คะแนน (เน้นความเร็ว/เน้นความแม่น) → เปิดห้องรอ
```

- ทุกข้อที่ AI ร่างมีป้าย **"ร่างโดย AI · ครูต้องตรวจ"** และแผง **"ที่มาในเอกสาร"** แสดงประโยคต้นฉบับ
- ระบบตรวจแบบ deterministic ว่าประโยคต้นฉบับมีอยู่จริงในเอกสาร ถ้าไม่เจอ → ป้ายเตือนสีเหลือง
- ปุ่ม `ร่างข้อนี้ใหม่` รายข้อ · fallback `เขียนเอง`

### 3.2 Lobby

- ครูแตะชื่อผู้เล่นแล้วเลือก `เอาออกจากเกม` ได้ (ชื่อขึ้นจอโปรเจกเตอร์ ต้องจัดการชื่อไม่เหมาะสมได้ทันที)
- ระบบกรองคำไม่สุภาพพื้นฐานไทย/อังกฤษก่อนแสดงชื่อ
- เข้าร่วมระหว่างเกมได้ เริ่มนับตั้งแต่ข้อถัดไป

### 3.3 กฎเลือกรอบทบทวน (ค่าเริ่มต้น = Assumption ปรับใน pilot)

```
สำหรับแต่ละมโนทัศน์ c:
  base(c)      = จำนวนคำตอบทั้งหมดในข้อที่มีตัวลวงผูกกับ c
  wrongShare(c) = คำตอบที่เลือกตัวลวงของ c ÷ base(c)
  ตัดทิ้งถ้า base(c) < 5          ← กันข้อมูลน้อยจนระบุตัวได้และลด noise
  "เด่น" ถ้า wrongShare(c) ≥ 20%
รอบทบทวน = ข้อทบทวนของมโนทัศน์ "เด่น" 3 อันดับแรก
  ถ้าเด่น < 3 → เติมจากคลังตาม wrongShare มากไปน้อย
  ถ้าไม่มีเด่นเลย → แสดง "ยังไม่มีจุดที่ควรทบทวนเป็นพิเศษ" ครูเลือกเล่น 3 ข้อจากคลังหรือจบเกม
ครูกด `เปลี่ยนข้อ` สลับกับข้ออื่นในคลังที่อนุมัติแล้วได้ ก่อนเริ่มรอบ
```

### 3.4 หน้าจุดที่ควรทบทวน (จอครู)

แสดงต่อมโนทัศน์: ชื่อ · wrongShare · ฐานนับ (base) · ข้อที่เกี่ยวข้อง · ข้อทบทวนที่ระบบเลือก — **ไม่มีชื่อนักเรียน**
v0 ไม่มีผลรายชื่อเล่น (ดูเรื่องที่ต้องตัดสินใจ §6)

## 4. Microcopy ที่เปลี่ยนหรือเพิ่ม (ที่เหลือใช้ตาราง ChatGPT §5)

| บริบท | ข้อความ | ปุ่ม |
|---|---|---|
| ทุกแถวที่มี "ซ่อม" | เปลี่ยนเป็น "ทบทวน" ตาม §2 | – |
| ข้อทบทวนไม่ครบ | ต้องมีข้อทบทวนที่ครูอนุมัติอย่างน้อย 3 ข้อ | `ไปที่คลังข้อทบทวน` |
| ผลคำตอบยังไม่พร้อม | กำลังรวบรวมคำตอบ… | **ไม่มีปุ่ม** (ของเดิมมีปุ่ม `รอสักครู่` ซึ่งกดแล้วไม่มีผล) |
| AI กำลังร่าง | กำลังร่างคำถามจากเอกสาร… | `ยกเลิก` |
| AI ร่างไม่สำเร็จ | ร่างคำถามไม่สำเร็จ ลองอีกครั้ง หรือเขียนคำถามเอง | `ลองอีกครั้ง` · `เขียนเอง` |
| ป้ายข้อจาก AI | ร่างโดย AI · ครูต้องตรวจ | – |
| แผงต้นฉบับ | ที่มาในเอกสาร | – |
| หาต้นฉบับไม่เจอ | ไม่พบประโยคนี้ในเอกสาร ตรวจข้อนี้เป็นพิเศษ | `ร่างข้อนี้ใหม่` · `แก้ไข` |
| PDF ยาวเกิน | เอกสารยาวเกิน {n} หน้า เลือกช่วงหน้าที่ใช้สอนคาบนี้ | `เลือกหน้า` |
| PDF เป็นภาพสแกน | อ่านข้อความจากไฟล์นี้ไม่ได้ ลองวางข้อความแทน | `วางข้อความ` |
| โหมดผู้เล่น | เล่นรายคน / เล่นเป็นกลุ่ม | toggle |
| คำอธิบายโหมดกลุ่ม | ให้แต่ละกลุ่มใช้เครื่องเดียว แล้วใส่ชื่อกลุ่ม | – |
| ช่องชื่อ (โหมดกลุ่ม) | ชื่อกลุ่ม | `เข้าร่วมเกม` |
| โหมดคะแนน | เน้นความเร็ว / เน้นความแม่น | toggle |
| คำอธิบายเน้นความแม่น | ตอบถูกได้คะแนนเท่ากัน ไม่ว่าจะตอบเร็วหรือช้า | – |
| ครูเอาผู้เล่นออก | เอา {ชื่อ} ออกจากเกม? | `เอาออก` · `ยกเลิก` |
| ผู้เล่นถูกเอาออก | ครูนำชื่อนี้ออกจากเกม ใส่ชื่อใหม่เพื่อเข้าร่วมอีกครั้ง | `เปลี่ยนชื่อ` |
| เข้าระหว่างเกม | เกมเริ่มแล้ว คุณจะเริ่มเล่นตั้งแต่ข้อถัดไป | – |
| สลับข้อทบทวน | – | `เปลี่ยนข้อ` |
| ไม่มีจุดเด่น | ยังไม่มีจุดที่ควรทบทวนเป็นพิเศษ | `เล่นข้อทบทวน 3 ข้อ` · `จบเกม` |

## 5. Accessibility และ Game feel

- ใช้ Game feel และ reduced motion ของ ChatGPT §6 ทั้งหมด · ค่าเริ่มต้นเสียง (เปิด/ปิด) ทดสอบใน pilot
- ตัวเลือกแสดง **ตัวอักษร ก ข ค ง + รูปทรง + สี + ข้อความ** ไม่พึ่งสีอย่างเดียว
- ปุ่มบนมือถือสูง ≥ 48px · contrast ผ่าน WCAG AA · โจทย์บนจอ host อ่านได้จากท้ายห้อง
- คีย์บอร์ดฝั่ง host: `Enter` = ปุ่มหลักของจอนั้น · `M` = เปิด/ปิดเสียง · `Esc` = หยุดชั่วคราว
