## 2. ช่องโหว่ที่ต้องแก้ก่อนเขียนโค้ด

1. **นับเงินที่ยังไม่เกิดเป็นยอดจริง (A, C)** — ใน brief A รายการเงินเดือนซ้ำ "วันที่ 28" ถูกนับเป็นรายรับเดือนนี้ แม้วันนี้ยังเป็นวันที่ 25 ผู้ใช้จะเห็นเงินที่ยังไม่ได้รับ → แก้ด้วยการแยก `RecurringRule` ออกจาก `Transaction` (ข้อ D5)
2. **โอนระหว่างบัญชีกับจ่ายบัตรเครดิต (A, C)** — ถ้าไม่มีชนิด transfer ผู้ใช้จะจดการจ่ายยอดบัตรเป็นรายจ่ายซ้ำกับการรูดบัตร → ยอดจ่ายเกินจริง ตามชุดทดสอบของ B
3. **เปลี่ยนราคาแล้วประวัติเพี้ยน (A)** — `Item` เดียวเก็บราคาปัจจุบัน แก้ราคาแล้วยอดเดือนก่อนเปลี่ยนตาม → ถ้าเงินจริงเป็น transaction แยก ปัญหานี้หายเองโดยไม่ต้องมี price_history ใน v0
4. **คำว่า "คงเหลือ" (A)** — สื่อว่าเป็นยอดในบัญชีธนาคาร ซึ่งแอปไม่รู้ → เปลี่ยนเป็น "สุทธิรอบนี้" (ข้อ D9) *นี่คือการแก้ copy ที่ brief A ล็อกไว้ ต้องให้ Grape อนุมัติ*
5. **FX ย้อนหลัง (A, C)** — แก้เรทแล้วยอดบาทของรายการเก่าเปลี่ยน → เก็บ `fxRate` ไว้ในแต่ละ transaction ตอนยืนยัน
6. **เงินเป็น float (A, C)** — `amount: number` แบบทศนิยมทำให้ผลรวมคลาดเป็นสตางค์ → เก็บเป็นหน่วยย่อย (`amountMinor` integer) ตาม B
7. **ไฟล์อ้างอิงที่ขาด (A)** — `รู้เงิน-scope-2026-09-25.md` และ `roongern/index.html` ไม่อยู่ในสิ่งที่ส่งมา ถ้ามีให้ใส่ใน `docs/reference/` ก่อนเริ่ม ถ้าไม่มีก็ build ได้จากเอกสารชุดนี้
8. **Claim ภายนอกยังไม่ได้ตรวจ (B)** — เรื่อง Open Data ของ ธปท. และหน้าเว็บ Wallet/Billbook ผมยังไม่ได้ตรวจเอง ใช้ได้เป็นบริบท แต่ห้ามใส่เป็นข้อความในแอป
