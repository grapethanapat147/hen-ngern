## 1. ปัญหา

**Problem statement (Assumption):** ครูมัธยมไทยใช้เกมควิซปลุกห้องได้ แต่พอเกมจบ สิ่งที่ได้คือ % ถูกรายข้อและอันดับ ครูต้องเดาเองว่านักเรียน "เข้าใจผิดเรื่องอะไร" และไม่มีข้อทบทวนที่พร้อมใช้ในคาบ ของที่ Kahoot มีคือการสร้างเกมใหม่จากข้อยากเดิม (G1) ซึ่งเป็นการเล่นซ้ำ ไม่ได้บอกสาเหตุ

**JTBD:** เมื่อสอนจบหัวข้อหนึ่ง ฉันอยากรู้ภายในคาบว่านักเรียนเข้าใจผิดตรงไหน และทบทวนได้ทันทีโดยไม่ต้องออกข้อสอบและวิเคราะห์ผลเอง

**H3 (แยกออกมา ยังไม่อยู่ใน v0):** ผลก่อน–หลังจากเกมช่วยเป็นหลักฐาน วPA ด้านที่ 2 — อ่อนลงเพราะด้านที่ 2 ต้องการร่องรอยผลงานผู้เรียน (G4) และเกณฑ์อาจเปลี่ยนตาม ว 12/2569 (Unknown)

**Unknown:** ครูใช้ผลหลังเกมอย่างไร · สัดส่วนห้องที่ใช้มือถือได้นอก กทม. · ครูจ่ายเงินเองหรือไม่ · ครูต้องการผลรายคนหรือรายข้อ

## 4. Value Proposition (VPC)

**Customer profile — ครูมัธยม**
- Jobs: ทบทวนท้ายหน่วย/ก่อนสอบ · เช็กความเข้าใจ · ทบทวนจุดที่ผิด · ทำให้ห้องมีส่วนร่วม · (รอง) เก็บหลักฐานผลลัพธ์
- Pains: ออกข้อสอบใช้เวลา · ผลเกมไม่บอกสาเหตุ · ไม่มีข้อทบทวนพร้อมใช้ในคาบ · มือถือใช้ได้ไม่ทุกคาบ
- Gains: ห้องสนุก · รู้ทันทีว่าต้องทบทวนเรื่องไหน · ไม่เสียเวลาคาบเพิ่ม

**Value map**
- Pain relievers: AI ร่างคำถาม + ตัวลวง + ข้อทบทวนจากเอกสารของครู พร้อมประโยคต้นฉบับกำกับ · ระบบเลือกข้อทบทวนจากคลังที่อนุมัติแล้วโดยอัตโนมัติ · โหมดกลุ่ม
- Gain creators: หน้าจุดที่ควรทบทวนแบบไม่ระบุชื่อ · รอบทบทวนไม่คิดอันดับ

**VP statement (ร่าง):**
> สำหรับครูมัธยมที่อยากรู้ว่าห้องเข้าใจผิดตรงไหนโดยไม่ต้องวิเคราะห์ผลเอง Quiz Loop เปลี่ยนเอกสารการสอนเป็นเกมควิซสดที่จบด้วยจุดที่ควรทบทวน และข้อทบทวน 3 ข้อที่ครูอนุมัติไว้แล้ว พร้อมเล่นต่อได้ทันทีในคาบเดียว

## 5. Game Loop (ในหนึ่งเกม)

```
[ก่อนคาบ] ครูอนุมัติข้อหลัก 5–10 ข้อ + คลังข้อทบทวน (1 ข้อ/มโนทัศน์, ≥ 3 ข้อ)
[ในคาบ]  lobby → คำถาม (อ่าน 3–5 วิ) → ตอบบนมือถือ (จับเวลา)
         → เฉลย + กราฟ + เหตุผล → คะแนน → top 5 (ทุก 3 ข้อ) → … → podium
         → จุดที่ควรทบทวน (จอครู, ไม่มีชื่อ)
         → ระบบเลือกข้อทบทวน 3 ข้อจากมโนทัศน์ที่ผิดมากสุด (ครูสลับได้)
         → รอบทบทวน ไม่คิดอันดับ → สรุปหลังเกม
```
กฎเลือกข้อทบทวนอยู่ใน `03-ux-spec-v1.md` §3.3

## 6. Usage Loop (นิสัยการใช้ของครู)

| ขั้น (Hook) | สิ่งที่เกิดขึ้น |
|---|---|
| Trigger | จบหัวข้อ / ก่อนสอบ / warm-up ต้นคาบ → ต่อมาเป็นสรุปรอบก่อนที่บอกว่า "หัวข้อนี้ยังมีจุดที่ควรทบทวน" |
| Action | อัปโหลด/วางเอกสาร → ตรวจคำถาม + คลังข้อทบทวน → เปิดเกม |
| Variable reward | ห้องคึก + ได้รู้ว่าเด็กผิดเพราะอะไรในแต่ละครั้ง |
| Investment | คลังคำถามและมโนทัศน์สะสม → ครั้งต่อไปเตรียมเร็วขึ้น · (H3) ผลก่อน–หลังสะสม |

**ความเสี่ยงของ loop (Assumption):** การต้องอนุมัติคลังข้อทบทวนเพิ่มเวลาเตรียม → วัดเวลาเตรียมจริงใน pilot (เป้า ≤ 10 นาที)

## 7. ขอบเขต MVP (Prototype v0 — เริ่มหลังผ่าน Gate 1)

**Must**
1. ครูล็อกอิน Google
2. สร้างจากข้อความที่วางหรือ PDF แบบข้อความ → AI ร่างข้อหลัก + มโนทัศน์ ≤ 5 เรื่อง + คลังข้อทบทวน พร้อม `sourceQuote` ทุกข้อ
3. ตรวจ `sourceQuote` แบบ deterministic ว่ามีในเอกสารจริง · ครูอนุมัติทุกข้อ · เปิดเกมไม่ได้ถ้ายังมีข้อรอตรวจหรือคลังข้อทบทวน < 3
4. เล่นสด: PIN + QR, รายคน/กลุ่ม, lobby ที่ครู **เอาผู้เล่นออกได้**, จับเวลา, เฉลย + กราฟ + เหตุผล, คะแนน 2 โหมด, top 5, podium
5. จุดที่ควรทบทวน (นับแบบ deterministic ไม่ใช้ LLM) + เลือกข้อทบทวนตามกฎ + ครูสลับข้อได้
6. รอบทบทวน 3 ข้อ ไม่คิดอันดับ + สรุปหลังเกมแบบรวม

**Should:** export CSV · ผู้เล่น refresh แล้วกลับเข้าเกมเดิม · เข้าร่วมระหว่างเกม

**Won't (v0):** หลักฐาน PA (H3, ทดสอบแบบ Wizard-of-Oz ก่อน) · ผลรายชื่อเล่น (รอคำตอบจากสัมภาษณ์) · AI สร้างข้อระหว่างคาบ · บัญชีนักเรียน · การบ้าน · avatar/power-up · รูป/วิดีโอในคำถาม · marketplace · LMS · ระบบจ่ายเงิน

**Acceptance criteria**
- ผู้เล่นจำลอง 40 คนตอบพร้อมกัน ไม่มีคำตอบหาย · timestamp และการคิดคะแนนอยู่ฝั่ง server
- "ส่งคำตอบแล้ว" แสดงหลัง server ตอบรับเท่านั้น
- ครูใหม่จากอัปโหลดถึงเปิดเกม ≤ 10 นาที (วัดใน usability test)
- จอ host 16:9 อ่านได้จากท้ายห้อง · ผู้เล่นใช้ได้บน iOS Safari และ Android Chrome
- host ใช้คีย์บอร์ดได้ · รองรับ `prefers-reduced-motion` · ตัวเลือกไม่พึ่งสีอย่างเดียว
- ไม่เก็บข้อมูลส่วนบุคคลนักเรียน · ไม่ส่งข้อมูลรายคนเข้า LLM

## 8. AI Spec และ Evaluation

| เรื่อง | ข้อกำหนด |
|---|---|
| งานของ AI | (1) ร่างข้อหลัก + ตัวลวง (2) จัดกลุ่มตัวลวงเป็นมโนทัศน์ ≤ 5 เรื่อง (3) ร่างข้อทบทวน 1 ข้อต่อมโนทัศน์ — **ทั้งหมดเกิดก่อนคาบ** |
| ไม่ใช้ AI | การนับ wrongShare, การเลือกข้อทบทวน, การคิดคะแนน |
| Output | structured JSON (zod) ผ่าน Vercel AI SDK · ทุกข้อมี `sourceQuote` + `conceptId` |
| Model | เทียบรุ่นเล็ก vs กลางบน eval set แล้วค่อยเลือก · ต้นทุนต่อชุด = วัดจริง |
| Eval set | ชุดแรกมาจาก concierge (ร่าง AI + สิ่งที่ Grape/ครูแก้) · เพิ่มเป็น 30 ชุดเอกสาร (3 วิชา × ม.ต้น/ม.ปลาย) ก่อน pilot |
| Rubric (Grape + ครู 1 คน) | ถูกต้องและมีคำตอบเดียว · อยู่ในต้นฉบับ · ตัวลวงสมเหตุสมผล · ตัวลวงสะท้อนมโนทัศน์ที่ติดป้ายจริง · ข้อทบทวนวัดมโนทัศน์เดียวกันแต่ไม่ซ้ำข้อเดิม · ภาษาไทยเป็นธรรมชาติ · เหมาะกับระดับชั้น |
| เป้า (ปรับได้) | ถูกต้อง ≥ 90% · อนุมัติโดยไม่แก้ ≥ 70% · ข้อผิดที่ถึงนักเรียน = 0 |
| Failure handling | ครูอนุมัติทุกข้อ · ป้ายเตือนเมื่อหา `sourceQuote` ไม่เจอ · ร่างใหม่รายข้อ · fallback เขียนเอง · ถ้าจัดกลุ่มมโนทัศน์ไม่ผ่านเกณฑ์ ให้แสดงแค่ % ถูกรายข้อ (ตามข้อเสนอของ Grok) |
| Privacy | ชื่อเล่น/ชื่อกลุ่มเท่านั้น · base < 5 ไม่แสดง · เอกสารต้นฉบับไม่เก็บถาวร (ต้องตรวจเรื่องลิขสิทธิ์หนังสือเรียน) |
| Integrity | ส่งออกได้เฉพาะข้อมูลจริงจากห้อง ห้ามสร้างหลักฐานแทนครู |

## 9. Tech (stack เดิมของ Grape)

Next.js App Router + TypeScript + Tailwind v4 + shadcn/ui + Framer Motion · Supabase (Auth, Postgres, Realtime Broadcast/Presence) · Vercel AI SDK

- คำตอบบันทึกผ่าน server (insert + server timestamp) ไม่ใช่ broadcast จาก client
- Supabase Free 200 connections / 100 msg/s (F9) พอสำหรับ pilot 1–2 ห้อง **แต่ต้อง load test** เรื่อง broadcast เฉลยไปยัง 40 คน

**Data model ร่าง:** `quizzes` · `concepts` (quizId, label) · `questions` (kind: main|review, stem, options[], correctIndex, conceptIdByOption, explanation, sourceQuote, sourceQuoteFound, approved) · `sessions` (pin, status, playerMode, scoringMode) · `players` (displayName, sessionId, removed) · `answers` (playerId, questionId, optionIndex, serverTs, points)
