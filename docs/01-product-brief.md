# 01 — Product & UX Brief: เห็นเงิน v0

> เอกสารหลักสำหรับ UI/UX · กฎคำนวณอยู่ที่ `02-domain-rules.md` · กฎ parser อยู่ที่ `03-parser-spec.md`

## 1. สินค้าในประโยคเดียว

**เห็นเงิน — เงินเข้า เงินออก และวันตัด ในก้อนเดียว** (tagline ชั่วคราว รอ Grape เลือก · ดู `07-next-tasks.md` §4)

สมุดเงินส่วนตัวภาษาไทยที่จดได้ด้วยประโยคเดียว แยกเงินที่เกิดขึ้นจริงออกจากบิลที่กำลังจะมา และไม่เชื่อมบัญชีธนาคาร

## 2. ผู้ใช้และงานที่ต้องจบ

**ผู้ใช้หลัก:** คนทำงานไทยอายุ 22–40 ใช้มือถือเป็นหลัก มีบัตร/วอลเล็ตหลายใบ จ่ายค่า SaaS/AI เป็น USD มีรายรับจากงานประจำและงานเสริม และไม่ยอมเชื่อมบัญชีธนาคาร

**ผู้ใช้รอง:** ฟรีแลนซ์ที่อยากแยกเงินงานกับเงินส่วนตัว (ใช้ป้าย `งาน` ได้ แต่ไม่บังคับ)

| # | Job | เกณฑ์ผ่าน |
|---|---|---|
| J1 | รู้ว่ารอบนี้เข้าจริงเท่าไร ออกจริงเท่าไร และจะโดนตัดอีกเท่าไร | ตอบได้ใน 5 วินาทีหลังเปิดแอป โดยไม่ต้องเลื่อน (390×844) |
| J2 | จดรายการด้วยประโยคเดียว | จากโฟกัสช่องพิมพ์ถึงบันทึกสำเร็จ ≤ 10 วินาทีสำหรับเคสง่าย |
| J3 | เห็นบิลหรือช่วงทดลองที่จะถึงใน 7 วัน | อยู่บนหน้าแรก |
| J4 | รู้ว่างานเสริมขาดจากเป้าอีกเท่าไร | แถบความคืบหน้าบนหน้าแรก |
| J5 | รู้ว่าวันไหนเงินออกเยอะ | ปฏิทินเดือน |

## 3. หลัก UX ที่ห้ามผิด

1. **Answer first** — หน้าแรกตอบ J1 ก่อนเลื่อน
2. **ร่างก่อนบันทึก** — ประโยคที่แปลงแล้วต้องแสดงเป็นร่างให้แก้ ห้ามเขียนลงสมุดเงียบๆ
3. **จริงกับคาดการณ์ไม่ปนกัน** — ทุกจำนวนเงินมีป้ายว่า *เกิดขึ้นแล้ว* หรือ *คาดว่าจะเกิด* ด้วยข้อความ ไม่ใช่แค่สี
4. **ทุกยอดต่างสกุลมีบาทคู่** — `US$20 ≈ ฿665` พร้อมบอกว่าใช้เรทไหน
5. **ตัวอย่างไม่ปลอมเป็นของจริง** — ข้อมูลตัวอย่างติดป้ายทุกจุด
6. **ไม่เชื่อมแบงก์คือจุดขาย** — เขียนบนหน้าแรกและหน้าตั้งค่า ไม่เขียนแบบขอโทษ
7. **มือถือก่อน** — ช่องพิมพ์และปุ่มหลักใช้นิ้วโป้งถึงได้
8. **ความเห็นจากสมุดเท่านั้น** — insight คำนวณจากรายการที่มีอยู่ ห้ามเดา
9. **ไม่ใช่แชทบอท** — ไม่มีบับเบิลแชท

## 4. Information architecture

```
เห็นเงิน
├── แถบพิมพ์ประโยค  (อยู่ใต้ header ทุกหน้า)
├── ภาพรวม           ← หน้าแรก
├── เงินเข้า-ออก     ← transaction จริงทั้งหมด
├── รายการซ้ำ        ← rules + ครั้งถัดไป + trial
├── ปฏิทิน           ← ทั้งจริงและคาดการณ์ในเดือน
└── เป้าและตั้งค่า
```

- Mobile (< 900px): bottom nav 5 ช่อง พร้อม safe-area inset
- Desktop (≥ 900px): sidebar ซ้าย เนื้อหากว้างสุด ~1180px
- Sheet: ยืนยันร่าง · เพิ่ม/แก้รายการ · เพิ่ม/แก้รายการซ้ำ · บัญชี · ยืนยันลบ · ยืนยันโหลดตัวอย่าง
- Mobile ใช้ bottom sheet (ไม่โดนคีย์บอร์ดบัง) · Desktop ใช้ side panel กว้าง ≤ 560px
- ห้ามเพิ่มแท็บใน v0

## 5. หน้าจอ

### 5.1 แถบพิมพ์ประโยค (ทุกหน้า)

- ป้าย: `พิมพ์เป็นประโยค แล้วตรวจร่างก่อนบันทึก`
- ช่องข้อความ 1 ช่อง + ปุ่ม `แปลง` · Enter = แปลง (เช็ก `isComposing`)
- Placeholder วนทีละข้อ: `ได้ค่างาน 4,500 เข้ากสิกร` · `จ่าย Netflix 419 ทุกเดือนวันที่ 5 บัตรกสิกร` · `ทดลอง Perplexity 20 ดอลลาร์ ถึง 2 ต.ค.` · `โอน 5,000 จากกสิกรไป SCB`
- ช่องว่าง → ปุ่มแปลงจาง
- แปลงไม่ได้ → ข้อความใต้ช่อง `ใส่ยอดเป็นตัวเลข เช่น จ่ายกาแฟ 65` (ไม่เปิดฟอร์มว่าง)
- แปลงได้ → เปิด **sheet ยืนยันร่าง** (5.2)
- ประโยคที่มีหลายรายการ (คั่นด้วย `,` หรือขึ้นบรรทัด) → ร่างหลายใบใน sheet เดียว

### 5.2 Sheet ยืนยันร่าง — `ตรวจข้อมูลก่อนบันทึก`

ร่าง 1 ใบ มี:

- ชนิด: segmented `รายรับ / รายจ่าย / โอน / คืนเงิน`
- ชื่อ · ยอด + สกุล (แสดง `≈ ฿…` ถ้าไม่ใช่บาท) · วันที่ · หมวด · บัญชี (โอน: จาก → ไป)
- รูปแบบ: `ครั้งเดียว / ทุกสัปดาห์ / ทุกเดือน / ทุกปี` — ถ้าไม่ใช่ครั้งเดียว ร่างนี้จะกลายเป็น **รายการซ้ำ** และแสดงช่อง วันสิ้นสุด / จบหลังกี่ครั้ง / ทดลองใช้ถึง
- ป้ายงาน (toggle `งาน`) แสดงเฉพาะเมื่อเปิดใช้ในตั้งค่า
- ช่องที่ parser ไม่แน่ใจ: พื้นเหลืองอ่อน + ข้อความ `ตรวจช่องนี้` แก้แล้วหายทันที
- **คำถามบังคับ** เมื่อกำกวม (ต้องเลือกก่อนบันทึกได้):
  - `จ่ายบัตร 8,000` → `รายการนี้เป็นการจ่ายยอดบัตร (โอน) หรือค่าใช้จ่ายใหม่?`
  - `โอน 2,500` ที่ไม่รู้ปลายทาง → `โอนให้คนอื่น (รายจ่าย) หรือโอนเข้าบัญชีของคุณเอง?`
- ถ้าตรงกับ occurrence ของรายการซ้ำที่ยังไม่จ่าย (±3 วัน, ชื่อคล้าย) → แถบ `ตรงกับ Netflix วันที่ 5 ต.ค. — บันทึกเป็นการจ่ายรอบนี้?` [จับคู่] [ไม่ใช่]

ปุ่ม: `ยกเลิก` · `บันทึก` (disabled ถ้าไม่มีชื่อ, ยอด ≤ 0 หรือยังไม่ตอบคำถามบังคับ — บอกด้วยข้อความว่าขาดอะไร)
หลังบันทึก: ปิด sheet · toast `บันทึกแล้ว` + `เลิกทำ` · ล้างช่องพิมพ์

### 5.3 ภาพรวม

บนสุดไปล่างสุด (สิ่งที่อยู่เหนือพับบน 390×844 คือข้อ 1–2):

1. Header: ชื่อรอบ `รอบ 1–31 ต.ค.` (หรือ `25 ก.ย. – 24 ต.ค.`) + ปุ่มเลื่อนรอบ ‹ ›
2. **4 ตัวเลข** (มือถือ 2×2)

   | ช่อง | ค่า | ป้าย |
   |---|---|---|
   | รับจริง | ผลรวม income ในรอบ | เกิดขึ้นแล้ว |
   | จ่ายจริง | ผลรวม expense − refund ในรอบ | เกิดขึ้นแล้ว |
   | สุทธิรอบนี้ | รับจริง − จ่ายจริง | บรรทัดเล็ก: `ไม่ใช่ยอดในบัญชี` |
   | จะตัดอีก | ผลรวม expected expense ที่ยังไม่จ่าย ตั้งแต่วันนี้ถึงสิ้นรอบ | คาดว่าจะเกิด |

3. **งานเสริม** — `฿12,500 / เป้า ฿10,000` + แถบความคืบหน้า (คิดจาก income หมวด `งานเสริม` ที่เกิดจริง)
4. **ช่วงทดลองใช้ฟรี** (ถ้ามี) — การ์ดพื้นปะการังอ่อน: ชื่อ, `เหลือ N วัน`, ยอดที่จะเริ่มหัก, `ยกเลิกก่อนหมด = ไม่โดนหัก`
5. **ใกล้ตัดใน 7 วัน** — ทั้งเงินออกและเงินเข้าที่คาดไว้ แต่ละแถวมีปุ่ม `จ่ายแล้ว` / `ได้รับแล้ว`
6. **เลยกำหนด ยังไม่ยืนยัน** (ถ้ามี) — occurrence ที่ผ่านวันแล้วแต่ยังไม่จับคู่ ไม่นับในยอดจริง
7. **บัญชี** — การ์ดเลื่อนแนวนอน: ชื่อ, ••4 ตัวท้าย, จ่ายจริงรอบนี้, จำนวนรายการ (ไม่ใช่วงเงิน/ยอดคงเหลือ)
8. **ความเห็นจากสมุด** 4–6 ข้อ เฉพาะที่คำนวณได้:
   - หมวดที่จ่ายมากสุดและสัดส่วน
   - วันที่จ่ายหนักสุด
   - บัญชีที่โดนหนักสุด
   - งานเสริมขาดจากเป้าเท่าไร
   - ถ้าจ่ายจริง > รับจริง → `รอบนี้เงินออกมากกว่าเข้า ลองดูรายการซ้ำที่ยังใช้อยู่` (ห้ามพูดว่า "คุณใช้เกิน")
   - บิลซ้ำเฉลี่ยต่อเดือน (รายปีหาร 12)
   - แต่ละข้อลิงก์ไปยังรายการต้นทางได้

### 5.4 เงินเข้า-ออก

- เลือกรอบ ‹ › · ค้นหาชื่อ · ชิปกรอง: `ทั้งหมด / รายรับ / รายจ่าย / โอน / งาน`
- จัดกลุ่มตามวัน (ใหม่ → เก่า) หัววันแสดงสุทธิของวันนั้น
- แถว: ไอคอนหมวด · ชื่อ · หมวด · บัญชี ••4 ตัวท้าย · ป้าย `ซ้ำ` ถ้า link กับ rule · ยอดบาท (`+` เขียวสำหรับรายรับ, `−` หมึกเข้มสำหรับรายจ่าย, `⇄` สีกลางสำหรับโอน) · สกุลต้นทางบรรทัดล่างถ้าไม่ใช่บาท
- Header แสดงผลรวมตามตัวกรองปัจจุบัน
- แตะแถว → sheet แก้ไข (มีปุ่มลบ)
- ปุ่ม `+ รายการ` เปิดฟอร์มเต็ม

### 5.5 รายการซ้ำ

- สรุปบน: จำนวน rule ที่ใช้อยู่ · เฉลี่ยต่อเดือน · ต่อปี (แยกเงินออก/เงินเข้า)
- รายการ (มือถือเป็นการ์ด, desktop เป็นตาราง): ฝั่ง · ชื่อ · รอบ · ราคาต้นทาง + ≈บาท · บัญชี · ครั้งถัดไป (`อีก N วัน`) · วันจบ/จำนวนครั้งที่เหลือ · ป้าย `ทดลองถึง …`
- ปุ่ม `+ บิลซ้ำ` (default รายเดือน, รายจ่าย)
- แก้ rule → ถามว่า `ใช้กับครั้งต่อไป` (default) · รายการจริงที่บันทึกแล้วไม่เปลี่ยน
- หยุดชั่วคราว / เลิกใช้ (ตั้ง `endsOn` = วันนี้) แทนการลบถ้ามีรายการจริงผูกอยู่

### 5.6 ปฏิทิน

- ตารางเดือน 7 คอลัมน์ เริ่มวันอาทิตย์ · วันนี้มีวงกลม
- เซลล์: ≤ 2 ป้ายสั้น (`+เงินเดือน`, `−Netflix`) + `+N` ถ้ามีมากกว่า · คาดการณ์ใช้เส้นประ/พื้นอ่อน, จริงใช้ทึบ
- วันที่จ่ายหนักสุดของเดือน: พื้นเหลืองอ่อน
- จอ < 400px: เซลล์เหลือเลขวัน + จุดสี (เข้า/ออก) แล้วแสดงรายการของวันที่เลือกด้านล่าง
- เลือกวัน → รายการของวันนั้น (จริงและคาดการณ์แยกหัวข้อ)
- สรุปบน: รวมจ่ายจริงเดือนนี้ · จำนวนครั้งที่ตัด · วันที่หนักสุด

### 5.7 เป้าและตั้งค่า

- **เป้างานเสริมต่อรอบ** (default 10,000) + แถบความคืบหน้า
- **วันเริ่มรอบ** 1–28 (default 1) + คำอธิบาย `ถ้าเงินเดือนออกวันที่ 25 ให้ตั้ง 25 รอบจะเป็น 25 ถึง 24 ของเดือนถัดไป`
- **เรท** USD→THB (default 33.25), EUR→THB (default 36.40) + `เรทนี้ตั้งเอง ไม่ใช่เรทเข้าบัญชี · รายการที่บันทึกแล้วใช้เรท ณ วันบันทึก`
- **ป้ายงาน** เปิด/ปิด (default ปิด)
- **บัญชี** เพิ่ม/แก้/ซ่อน: ชื่อ, ประเภท (บัตรเครดิต/บัญชีธนาคาร/วอลเล็ต/เงินสด/พร้อมเพย์), 4 ตัวท้าย (เฉพาะบัตร/วอลเล็ต), สีการ์ด — **ห้ามมีช่องเลขเต็ม, CVV, วันหมดอายุ**
- **ข้อมูล:** ส่งออก JSON · นำเข้า JSON (ยืนยันก่อนทับ) · ส่งออก CSV · โหลดข้อมูลตัวอย่าง (ยืนยัน) · ล้างข้อมูลในเครื่อง (ยืนยัน)
- **นโยบาย:** `ใช้ฟรีในเครื่องนี้ · ไม่เชื่อมบัญชีธนาคาร · ไม่เก็บเลขบัตรเต็ม · ข้อมูลไม่ขึ้นคลาวด์`

## 6. States

| สถานะ | พฤติกรรม |
|---|---|
| เปิดครั้งแรก | โหลดข้อมูลตัวอย่าง + แบนเนอร์ `ตัวอย่าง ไม่ใช่ยอดจริง` + ปุ่ม `เริ่มสมุดของฉัน` (ยืนยัน → สมุดว่าง → ไปตั้งค่า) |
| สมุดว่าง | 4 ตัวเลขเป็น ฿0 · แถบพิมพ์ + chip ตัวอย่าง 3 ประโยค · ส่วนอื่นแสดง empty text สั้น |
| localStorage อ่านไม่ได้/เสีย | เริ่มสมุดว่าง + แบนเนอร์ `อ่านข้อมูลเดิมในเครื่องไม่ได้ เริ่มสมุดใหม่แล้ว` + เก็บ raw เดิมไว้ใน key สำรอง |
| localStorage ใช้ไม่ได้ (private mode) | ใช้งานได้ในหน่วยความจำ + แบนเนอร์ `เบราว์เซอร์นี้ไม่ให้บันทึก ข้อมูลจะหายเมื่อปิดหน้า` |
| ฟอร์มไม่ครบ | ปุ่มบันทึก disabled + บอกช่องที่ขาด |
| ลบ | toast `ลบแล้ว` + `เลิกทำ` 5 วินาที |
| โหลดตัวอย่าง/นำเข้า/ล้าง | ยืนยันในหน้า (ห้ามใช้ `confirm()`) |
| ยอดหลายสกุลไม่มีเรท | แสดง `รออัตราแลกเปลี่ยน` และไม่รวมในยอดบาท |

- สถานะ: เกิดขึ้นแล้ว · คาดว่าจะเกิด · รอตรวจ · เลยกำหนด
- ปุ่ม: แปลง · บันทึก · ยกเลิก · ลบ · เลิกทำ · จ่ายแล้ว · ได้รับแล้ว · ส่งออก JSON · ส่งออก CSV · โหลดข้อมูลตัวอย่าง
- นโยบายสั้น: `ใช้ฟรีในเครื่องนี้ · ไม่เชื่อมบัญชีธนาคาร`
- ทดลอง: `ยกเลิกก่อนหมด = ไม่โดนหัก`
- เรท: `เรทนี้ตั้งเอง ไม่ใช่เรทเข้าบัญชี`
- ตัวอย่าง: `ตัวอย่าง ไม่ใช่ยอดจริง`
- น้ำเสียง: ชัด สั้น เป็นคนพูด ไม่ใช่แบงก์ ไม่ใช่โค้ชชีวิต · ห้ามใช้ "ปฏิวัติการเงิน", "AI อัจฉริยะ", "จัดการความมั่งคั่ง", "คุณใช้เกิน"

- ห้ามใช้กราฟวงกลมเป็นตัวหลักของหน้าแรก

- Light mode อย่างเดียวใน v0

## 9. Accessibility

- Target ≥ 44×44px · label ทุก input · focus ring ชัด · Esc ปิด sheet และคืน focus
- สถานะใช้ข้อความ + สี ไม่ใช้สีอย่างเดียว
- Toast `role="status"` · error `role="alert"`
- `prefers-reduced-motion` ปิดแอนิเมชัน
- จำนวนเงินอ่านได้ด้วย screen reader (`aria-label="รายจ่าย 419 บาท"`)
