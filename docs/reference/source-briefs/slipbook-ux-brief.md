## 1. Outcome ที่ต้องได้

ผู้ใช้ตอบได้ภายใน 5 วินาทีหลังเปิดแอปว่า **"รอบเงินเดือนนี้ เงินเข้าเท่าไร ออกเท่าไร และใช้ได้อีกวันละเท่าไร"** และบันทึก 1 รายการได้ภายใน **< 10 วินาที** ด้วยสลิปหรือข้อความสั้น

**Primary user:** คนทำงานไทยอายุ 22–35 มีหลายบัญชี/บัตร/วอลเล็ต (KBank, SCB, TrueMoney, เงินสด) โอน PromptPay ทุกวัน และมี subscription หลายตัว (บางตัวจ่ายเป็น USD)

**Job to be done:** "ตอนสิ้นเดือนผมไม่รู้ว่าเงินหายไปไหน และไม่อยากนั่งจดทีละรายการ"

**โมเดลธุรกิจ:** Ayno — mass AI product (แยกจาก client AI solutions)

---

## 2. สิ่งที่ล็อกแล้ว (ห้ามเปลี่ยนโดยไม่ถาม Grape)

1. ไม่เชื่อมธนาคาร ไม่ขอเลขบัตรเต็ม เก็บแค่เลข 4 ตัวท้าย
2. AI ทำหน้าที่ **ร่าง (draft)** เท่านั้น ทุกรายการต้องให้ผู้ใช้กดยืนยันก่อนบันทึก
3. ภาพสลิปส่งให้ AI อ่านครั้งเดียวแล้วทิ้ง ไม่เก็บบน server
4. ลองใช้ได้โดยไม่ต้องสมัคร (เก็บในเครื่อง) สมัครทีหลังแล้วย้ายข้อมูลขึ้นบัญชีได้
5. รอบเดือนนับตาม **วันเงินเดือนออก** ไม่ใช่วันที่ 1
6. รวมรายรับ + รายจ่าย + รายการซ้ำ (subscription/บิล/trial) ไว้ในแอปเดียว

## 4. UX Principles

1. **Capture first** — ช่องจดอยู่บนสุดของหน้าแรกเสมอ ไม่ต้องกดปุ่ม "+" ก่อน
2. **One number** — หน้าแรกมีตัวเลขเด่นตัวเดียว: "ใช้ได้อีกวันละ ฿…"
3. **AI proposes, human confirms** — แสดงผล AI เป็น draft แก้ได้ทุกช่อง ช่องที่ AI ไม่แน่ใจต้องเห็นชัด
4. **Graceful without AI** — ถ้า AI ใช้ไม่ได้ การพิมพ์สั้นยังทำงานด้วย parser ในเครื่อง; มีแค่การอ่านสลิปที่ต้องพึ่ง AI
5. **Thai-native** — ภาษาไทยเป็นหลัก รู้จักคำอย่าง "เมื่อวาน", "5k", "พัน", ปี พ.ศ., ชื่อธนาคารไทย

## 5. Information Architecture

```
Bottom nav (mobile) / Sidebar (desktop ≥ 900px)
├── ภาพรวม        ← หน้าแรก: Capture + ตัวเลขรอบนี้ + trial + ตัดเงินใน 14 วัน + ล่าสุด
├── รายการ        ← ทุก transaction, ค้นหา/กรอง, แก้/ลบ, export CSV
├── รายการซ้ำ     ← subscription, บิล, ค่าเช่า, trial
└── ตั้งค่า        ← วันเงินเดือนออก, งบ, เรต USD, บัญชี/บัตร, ข้อมูล, ความเป็นส่วนตัว
```

## 6. Screens

### 6.1 ภาพรวม (Overview)

ลำดับจากบนลงล่าง:

1. **Header** — วันที่วันนี้ + pill "รอบเงินเดือน 25 ก.ย. – 24 ต.ค."
2. **Capture card** (ดู 6.2)
3. **Metric row (4 ช่อง)**
   - **ใช้ได้อีกวันละ** (hero, สี accent) · sub: "อีก N วันถึงรอบใหม่ · หักรายการซ้ำแล้ว"
   - รายรับรอบนี้ (สีเขียว) · จำนวนรายการ
   - รายจ่ายรอบนี้ (สีแดง) · จำนวนรายการ
   - รายการซ้ำที่จะตัดอีก · "ก่อนสิ้นรอบ {วันที่}"
4. **งบรอบนี้** — progress bar 2 ชั้น: ใช้ไป (แดง) + จองไว้สำหรับรายการซ้ำ (เหลือง) · ลิงก์ "ตั้งงบ/แก้งบ"
5. **แยกตามหมวด** — stacked bar + รายการหมวด (สี, ชื่อ, %, ยอด) เรียงมาก→น้อย
6. **ช่วงทดลองใช้ฟรี** (แสดงเมื่อมี) — การ์ดสีเหลือง: ชื่อ, ยอดที่จะเริ่มตัด (USD แสดง ≈ บาท), วันที่, ตัวเลขใหญ่ "N วันที่เหลือ" · หัวข้อรอง "ยกเลิกก่อนหมด = ไม่โดนตัดเงิน"
7. **ตัดเงินใน 14 วัน** — date box (วัน + เดือนย่อ) ไฮไลต์เมื่อ ≤ 3 วัน, ชื่อ, "อีก N วัน", ยอด
8. **ล่าสุด** — 6 รายการล่าสุด แตะเพื่อแก้

Desktop: ข้อ 4–5 อยู่คอลัมน์ซ้าย (1.15fr), 6–8 คอลัมน์ขวา (1fr) · Mobile: ทุกอย่างคอลัมน์เดียว metrics เป็น 2×2

### 6.2 Capture card

- Textarea (2 บรรทัด, ขยายได้) placeholder: `พิมพ์ได้หลายรายการ เช่น กาแฟ 65 tmn, ข้าว 50 เงินสด, เงินเดือนเข้า 35000`
- ปุ่ม **แยกรายการ** (primary) · Enter = ส่ง, Shift+Enter = ขึ้นบรรทัด (ต้องเช็ก `isComposing` สำหรับ IME)
- ปุ่ม **อัปโหลดสลิป** — เลือกได้หลายภาพ, รองรับ paste ภาพ, drag & drop บน desktop
- Thumbnails ของภาพที่เลือก (ลบทีละภาพได้) + ปุ่ม "อ่าน N สลิป" + ข้อความ "ภาพถูกส่งให้ AI อ่านครั้งเดียว แอปไม่เก็บภาพไว้"
- Example chips (แตะแล้วเติมลงช่อง): `กาแฟ 65 tmn, ข้าวมันไก่ 50 เงินสด` · `เงินเดือนเข้า 35000 kbank` · `Grab 142 เมื่อวาน` · `Netflix 419 scb`
- Status pill: "AI พร้อม" / "โหมดในเครื่อง (ไม่ใช้ AI)"
- **Loading state:** spinner + "กำลังให้ AI อ่าน…" + ปุ่ม "หยุด" (cancel request จริง)

### 6.3 Draft review (อยู่ใต้ capture card, ไม่ใช่ modal)

ต่อ 1 draft:

| ช่อง | Control | หมายเหตุ |
|---|---|---|
| ประเภท | Segmented: จ่าย / รับ | เปลี่ยนแล้วหมวดรีเซ็ตเป็น "อื่นๆ" ของประเภทนั้นและติด low-confidence |
| ยอด | Number input, `inputmode=decimal` | label บอกสกุล (บาท/USD) |
| รายการ | Text | ชื่อร้าน/ผู้รับ |
| หมวด | Select (ตามประเภท) | |
| บัญชี | Select + ตัวเลือก "— เลือก —" | |
| วันที่ | Date | default วันนี้ |
| ลบ | Ghost button | |

แถวล่างของ draft:

- Pill แหล่งที่มา: "อ่านจากสลิป" / "AI" / "ตัวแยกในเครื่อง"
- ถ้ามีช่อง low confidence → pill เหลือง "ช่องสีเหลือง = ไม่แน่ใจ ตรวจก่อน" และช่องนั้นพื้นเหลือง; **แก้ช่องนั้นแล้วสีเหลืองหายทันที**
- ถ้าตรวจพบว่าเป็น subscription (หมวด subs หรือชื่อตรง keyword และยังไม่มีในรายการซ้ำ) → checkbox "ดูเหมือน subscription · เพิ่มเป็นรายการซ้ำรายเดือน"

Footer: "AI ช่วยกรอกให้ แต่ยังไม่บันทึกจนกว่าคุณจะกดยืนยัน" · ปุ่ม **ยกเลิก** / **บันทึก N รายการ**
หลังบันทึก: toast "บันทึกแล้ว N รายการ · เพิ่มรายการซ้ำ M", ล้างช่องพิมพ์

Desktop: 1 draft = 1 แถว grid · Mobile: 2 คอลัมน์ (ประเภทและชื่อเต็มแถว)

### 6.4 รายการ (Transactions)

- Header: "รายการทั้งหมด" + eyebrow "N รายการ · รับ ฿… · จ่าย ฿…" (คำนวณตามตัวกรอง)
- ปุ่ม: ส่งออก CSV · + เพิ่มเอง
- Filters: ค้นหา (ชื่อ) · ประเภท · บัญชี · หมวด
- จัดกลุ่มตามวัน (ใหม่→เก่า) หัวกลุ่ม = วันที่แบบยาว + ยอดสุทธิของวัน
- Row: ไอคอนตัวอักษรแรกบนสีหมวด · ชื่อ · หมวด · บัญชี ••4 ตัวท้าย · badge "สลิป" ถ้ามาจากสลิป · ยอด (รายรับ +เขียว, รายจ่าย −)
- แตะ row → sheet แก้ไข (ฟิลด์เดียวกับ draft + สกุลเงิน) มีปุ่ม "ลบรายการ"

### 6.5 รายการซ้ำ (Recurring)

- Eyebrow: "N รายการ · เฉลี่ย ฿…/เดือน · ฿…/ปี"
- Metric ต่อบัญชี/บัตร: ยอดเฉลี่ยต่อเดือน (รายปีหาร 12)
- ตาราง: ตัดครั้งถัดไป (date box + "อีก N วัน") · บริการ (+ pill "ทดลองถึง …") · รอบ · ราคา (USD แสดง ≈ บาทบรรทัดล่าง) · ต่อเดือน · บัญชี
- Mobile: ตาราง scroll แนวนอนในกล่องตัวเอง (หน้าไม่ scroll แนวนอน)
- Footnote: "แปลง USD เป็นบาทด้วยเรตที่ตั้งไว้ (X บาท/USD)"
- Sheet เพิ่ม/แก้: ชื่อ · ราคา · สกุล · รอบ (เดือน/ปี) · วันตัดเงิน (ครั้งใดก็ได้) · บัญชี · หมวด · ทดลองฟรีถึงวันที่ (optional)

### 6.6 ตั้งค่า

- **รอบเดือนและงบ:** เงินเดือนออกวันที่ (1–28) · งบใช้จ่ายต่อรอบ · เรต USD→บาท · คำอธิบาย "ออกวันที่ 25 = รอบ 25 ถึง 24 ของเดือนถัดไป ถ้าไม่ตั้งงบจะใช้รายรับของรอบเป็นงบ"
- **บัญชี บัตร วอลเล็ต:** ชื่อ · ประเภท (บัญชีธนาคาร/บัตรเครดิต/วอลเล็ต/เงินสด) · เลข 4 ตัวท้าย · note "เก็บแค่ 4 ตัวท้ายไว้ให้ AI จับคู่สลิปกับบัญชี"
- **ข้อมูล:** จำนวนรายการ · ส่งออก CSV · โหลดข้อมูลตัวอย่าง · ล้างข้อมูลทั้งหมด (ต้องมีขั้นยืนยันในหน้า)
- **ความเป็นส่วนตัว:** ข้อความอธิบายว่าเก็บอะไร ส่งอะไรให้ AI

### 6.7 First run / ข้อมูลตัวอย่าง

- ผู้ใช้ใหม่เห็นแอปพร้อม **ข้อมูลตัวอย่าง** + แบนเนอร์เหลือง "ข้อมูลตัวอย่าง · ตัวเลขทั้งหมดเป็นตัวอย่าง ไม่ใช่ข้อมูลจริงของคุณ" + ปุ่ม "เริ่มใช้กับข้อมูลจริง"
- กด → ยืนยัน → ล้างเป็น state ว่าง → พาไปหน้าตั้งค่า + toast "ตั้งวันเงินเดือนออกและเพิ่มบัญชีได้เลย"
- ข้อมูลตัวอย่างต้องสร้างวันที่ **สัมพันธ์กับวันนี้** และอยู่ในรอบปัจจุบัน (ไม่ใช่ hard-code วันที่)

| ที่ | ข้อความ |

## 7. Business rules (ต้องทำตรงนี้)

**รอบเดือน**
- `payday` = 1–28 · ถ้าวันนี้ ≥ payday → start = payday ของเดือนนี้ ไม่งั้น start = payday ของเดือนก่อน · end = start + 1 เดือน − 1 วัน

**ใช้ได้อีกวันละ**
```
base      = budget > 0 ? budget : income_this_period
upcoming  = Σ รายการซ้ำที่จะตัดตั้งแต่พรุ่งนี้ถึง end (ข้ามครั้งที่ยังอยู่ในช่วง trial)
safe      = max(0, base − expense_this_period − upcoming)
per_day   = floor(safe / days_left)      // days_left รวมวันนี้
```

**รายการซ้ำ**
- เก็บ `anchor` (วันตัดครั้งใดก็ได้) + `cycle` (month/year) → คำนวณครั้งถัดไปแบบ dynamic
- วันที่ 29–31 ในเดือนที่ไม่มี: ตัดวันสุดท้ายของเดือน (prototype ยังไม่ได้ทำ — ต้องทำในเวอร์ชันจริง)
- ต่อเดือน = รายเดือน หรือ รายปี ÷ 12
- Trial: ถ้ามี `trialEnd` ≥ วันนี้ → แสดงการ์ด trial; ครั้งตัดเงินที่เกิดก่อน trialEnd ไม่นับใน upcoming
- เฟส backend: เพิ่ม `price_history` เพื่อให้ยอดย้อนหลังคิดตามราคาจริงแต่ละช่วง (แบบ Billbau)

**สกุลเงิน**
- MVP: THB + USD ด้วยเรตที่ผู้ใช้ตั้ง · เฟสถัดไป: ดึงเรตรายวัน (เช่น Frankfurter API) และเก็บเรต ณ วันที่ทำรายการ

## 8. AI behavior spec

**Input → Output**

- ข้อความ: prompt + บริบท (วันนี้ ค.ศ., รายการบัญชี id/ชื่อ/4 ตัวท้าย/ประเภท, รายการหมวด id/ชื่อ/ประเภท) + ข้อความผู้ใช้ (ตัดที่ 2,000 ตัวอักษร) · ใช้ model ระดับเร็ว
- สลิป: ภาพ ≤ ขีดจำกัดต่อครั้ง (prototype ใช้ 4) · 1 ภาพ = 1 รายการ · ใบเสร็จใช้ยอดสุทธิ · ภาพที่ไม่ใช่สลิปให้ข้าม

**Output schema (JSON array)**
```json
[{
  "type": "expense | income",
  "amount": 65,
  "currency": "THB | USD",
  "name": "กาแฟ",
  "category": "<category id>",
  "accountId": "<account id | ''>",
  "date": "YYYY-MM-DD",
  "confidence": { "amount": "high|low", "name": "high|low", "category": "high|low", "account": "high|low" }
}]
```

**กฎใน prompt**
- ไม่แน่ใจ → เดาค่าที่เป็นไปได้มากที่สุด + ใส่ `low` · **ห้ามแต่งยอดเงิน**
- แปลง พ.ศ. → ค.ศ. (−543) · ไม่มีวันที่ให้ใช้วันนี้
- `accountId` ต้องมาจากรายการที่ให้เท่านั้น จับคู่ด้วยชื่อธนาคาร + 4 ตัวท้าย
- สลิปโอนออก = expense, `name` = ผู้รับ/ร้าน

**Post-processing ฝั่งแอป (ห้ามเชื่อ AI ตรงๆ)**
- บังคับ type/category/account ให้อยู่ในชุดที่ถูกต้อง ไม่ตรง → fallback เป็น "อื่นๆ" / ว่าง
- amount ต้อง > 0 และ finite ไม่งั้นทิ้ง
- วันที่ไม่ใช่รูปแบบ YYYY-MM-DD → วันนี้

**Local parser (fallback เมื่อไม่มี AI)**
- แยกด้วย `,` `;` ขึ้นบรรทัด หรือ " และ "
- ตัวเลข + หน่วย: `k` (ต้องไม่ตามด้วยตัวอักษร — **กัน bug "35000 kbank" กลายเป็น 35 ล้าน**), `พัน`, `บาท`, `฿`, `$`, `usd`
- Account aliases: kbank/กสิกร/k plus · scb/ไทยพาณิชย์ · tmn/truemoney/ทรู · เงินสด/cash
- คำบ่งรายรับ: เงินเดือน รายได้ ได้รับ ฟรีแลนซ์ โบนัส คืนเงิน ขายของ ได้เงิน ค่าจ้าง
- "เมื่อวาน" → −1 วัน
- ช่องที่เดาไม่ได้ติด `low`

**Error → UX**

| สถานการณ์ | สิ่งที่ผู้ใช้เห็น |
|---|---|
| ไม่ได้รับอนุญาต / AI ปิด | "ใช้ AI ไม่ได้ในมุมมองนี้ เลยใช้ตัวแยกในเครื่องแทน" + ผล local parser |
| Rate limit | "เรียก AI ถี่เกินไป รอสักครู่แล้วลองใหม่" |
| ภาพอ่านไม่ได้ | "อ่านไฟล์ภาพนี้ไม่ได้ ลองใช้ภาพ JPG/PNG ที่ชัดกว่านี้" |
| JSON พัง / ว่าง | "AI ตอบกลับไม่ครบ ลองกดอีกครั้ง" |
| ไม่พบยอดเงิน | "ไม่พบยอดเงินในข้อความ ลองพิมพ์แบบ 'กาแฟ 65'" |
| ผู้ใช้กดหยุด | "ยกเลิกแล้ว" |

ห้าม retry อัตโนมัติแบบวนลูป

## 11. Accessibility & responsive

- ใช้งานได้ที่ 360px ขึ้นไป · ไม่มี horizontal scroll ระดับหน้า (ตารางเท่านั้นที่ scroll ในกล่อง)
- Breakpoint 900px: ต่ำกว่า = bottom nav (มี safe-area inset) · สูงกว่า = sidebar
- ทุก control มี label · focus ring เห็นชัด · row ที่แตะได้ต้องกดด้วย Enter/Space ได้ · Esc ปิด sheet
- Low confidence ต้องสื่อด้วยข้อความ ไม่ใช่สีอย่างเดียว
- `prefers-reduced-motion` ปิด animation
- Status/toast ใช้ `role="status"`
- ห้ามใช้ `alert/confirm` ของเบราว์เซอร์ — ยืนยันในหน้า

## 14. Acceptance criteria

1. พิมพ์ `กาแฟ 65 tmn, ข้าวมันไก่ 50 เงินสด, เงินเดือนเข้า 35000 kbank, Netflix 419 scb` → ได้ 4 drafts: ยอด 65/50/35000/419, รายการที่ 3 เป็นรายรับหมวดเงินเดือน, บัญชีถูกทั้ง 4, Netflix มี checkbox subscription
2. แก้ยอดใน draft แล้วบันทึก → ค่าที่แก้ถูกเก็บ, ช่องพิมพ์ถูกล้าง, toast แสดงจำนวน
3. ไม่มีรายการใดถูกบันทึกโดยไม่กดยืนยัน
4. อัปโหลดสลิป K PLUS / SCB / Krungthai / TrueMoney → ได้ยอด วันที่ ผู้รับ และจับคู่บัญชีจาก 4 ตัวท้าย
5. AI ใช้ไม่ได้ → พิมพ์สั้นยังได้ drafts จาก local parser พร้อมข้อความบอก
6. เปลี่ยนวันเงินเดือนออก → pill รอบเดือน, ตัวเลขรอบนี้ และ "ใช้ได้อีกวันละ" คำนวณใหม่ถูกต้อง
7. Trial ที่ยังไม่หมดแสดงการ์ดนับถอยหลัง และไม่ถูกนับใน upcoming
8. ค้นหา + กรองประเภท/บัญชี/หมวด ทำงานร่วมกัน และยอดรวมใน header ตามตัวกรอง
9. Export CSV มี BOM (เปิดใน Excel ไทยไม่เพี้ยน) คอลัมน์: date, type, name, amount, currency, amount_thb, category, account
10. 360px ไม่มี horizontal scroll ทุกหน้า · light/dark อ่านได้ครบ · ใช้ keyboard ได้ครบ flow
